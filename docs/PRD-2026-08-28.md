# PRD — The Agent Work Record Witness

**2026-08-28.** Written after the corpus run, not before it. Every figure below is cited to the file
that produced it; nothing is quoted from a brief. Where I ran something myself tonight it says so.

Supersedes nothing. The existing docs describe a gate on pull requests, and the product moved.

---

## 1 · What it is

**An append-only record of what your coding agents claimed, what the object said, and which session
said it.**

One sentence a buyer repeats: *"It keeps the receipts for what our agents said they did."*

Three surfaces, and they are not equal — take the position rather than listing them:

| | | |
|---|---|---|
| **The measurement** | the **wedge** | Point it at transcripts you already have. Nothing to install, nothing to adopt, a number in one command. |
| **The record** | the **product** | The thing that accumulates and the thing that gets renewed. Claims, verdicts, overrides, and the session behind each one. |
| **The gate** | the **intake** | How claims get into the record going forward. Necessary; not the pitch. |

**Why the measurement is the wedge and not the product.** The gate is a CI check, and CI checks are
a crowded, cheap category. The record is what nobody else holds — Zenity governs agent actions, Norm
Ai does content compliance, Qodo reviews the diff, Langfuse scores the trace, and **none of them
holds the transcript** (`README.md`, "The join is moment two"). But a record is worth nothing on day
one, by definition: it is empty. The measurement is what makes day one worth having, because it runs
against a month of output that already exists.

**This is the change from the old docs.** They open with *install the gate on your PRs*. That asks
for adoption before value. The corpus run inverted it: **measure first, adopt second.**

## 2 · The finding the product is now built around

`docs/ENTERPRISE-CASE-2026-08-27.md` §2, reproduced in `README.md` and `FILM-SHOT-LIST.md`, output
of `witness-corpus`:

```
  78,618 messages examined, of 144,306 in the corpus · 83 repos on disk
  RAW          247 sha claims ·  103 disagree · 41.7%
  CORRECTED    236 sha claims ·   19 disagree · 8.1%
```

**41.7% → 8.1%, and the entire gap was our own probe, not the agents.** 73 of the 103 "wrong" commit
claims were real commits in a sibling repo on the same disk — an agent's `cwd` is where it was
standing, not where it committed.

The sales line is not "agents lie 8% of the time." **It is "your first number will be wrong, and
here is the method that catches it."** `docs/CORPUS-PREREGISTRATION-2026-08-27.md` fixed the
denominator before anyone looked at a claim. That document is the method, and the method is what a
buyer is actually purchasing.

**Neither number is an incidence rate**, and the docs say so before anyone asks: hand-labelling 40
random extractions put precision on conversational prose at **13/40**, and of those 13 real claims 6
disagreed with the repo — **n = 13**, a direction, not a measurement
(`docs/CORPUS-MEASUREMENT-2026-08-27.md`). The sample ships as `fixtures/corpus-sample-40.json` so a
reader can re-label it and disagree.

## 3 · First user, and their first five minutes — as steps, not a promise

**First user: a platform or eng-productivity lead at an org already running a coding-agent fleet,
who has been asked "can you prove no agent shipped something unverified" and cannot.** Not a
security team, not a CISO. Someone with a fleet and no instrument.

I ran the following tonight against a clean clone of the public repo in a fresh venv.

| Min | Step | Measured result |
|---|---|---|
| 0–1 | `git clone` + `pip install -e .` | exit 0 |
| 1–2 | `witness --help` | exit 0, prints usage |
| 2–3 | `witness "Done. Committed as a41c9f2. Wrote src/cache.py."` | probes git and the filesystem, no database needed |
| 3–5 | `python3 gate/outcome_gate.py --json < fixtures/agent-false-done-PR-BODY.md` | **exit 1**, BLOCK on the false commit, PASS on the true path, UNVERIFIABLE on the test claim |

**That is a real, working five minutes and it needs no credentials and no transcript database.**

### The defect in the front door, measured tonight

The README's *"Start here"* section — the first command a reader meets — is `witness-corpus`. Its
`--db` defaults to `~/.trace/trace.db`. **A stranger does not have that file, and the tool does not
say so:**

```
$ witness-corpus --db /tmp/nope.db --code-root /tmp
Traceback (most recent call last):
  File ".../gate/corpus_scan.py", line 78, in scan
    db = sqlite3.connect(f"file:{...}?mode=ro", uri=True)
sqlite3.OperationalError: unable to open database file
exit 1
```

**The wedge is the front door, and the front door hands a stranger a stack trace.** This is the
single highest-value fix in the document and it is a few lines: detect the missing file, name it,
say what produces one, and point at `witness` — which works with nothing — as the thing to run
instead. Until then the README's opening command is a wall for everyone except this operator.

*(Fixed since the earlier cold-start report: `witness --help` returned exit 2 and was graded as a
work report. It now exits 0.)*

## 4 · What it does not do

Stated plainly, because a record product that overclaims has destroyed its only asset.

- **Installs by anyone who is not the author: zero.** Northwind, the test company, was written and
  scripted by us (`docs/ENTERPRISE-CASE-2026-08-27.md` §3). That run proves the chain — installs into
  a foreign repo, blocks a false claim at exit 1, clears a true one at exit 0. **It does not prove
  adoption.**
- **One shared bearer token. No per-agent identity.** Every agent in a fleet presents the same
  credential, so the record can say *an agent* claimed something, not *which* agent. For a product
  whose subject is attribution, this is the largest gap.
- **The session join is Claude Code only.** The gate is harness-agnostic — it reads a report as text
  and never parses a harness format. The join is not: measured against **427 real session trailers**,
  every one is `Claude-Session: https://claude.ai/code/session_<id>`. Codex, Cursor, Copilot, Devin
  and Aider get the gate and no join (`README.md`, "Which agent harnesses").
- **It never runs a command from a report.** A test claim comes back `UNVERIFIABLE`, refused rather
  than guessed. This is a deliberate limit, not a gap.
- **The extractor cannot tell a citation from a claim.** *"Commit X landed"* and *"Committed as X"*
  are the same string. On conversational prose its precision is 13/40.
- **One operator, one machine.** Nothing measured here generalises to a population.

## 5 · The next three things to build

**1 · Separate a citation from a claim.** The named open problem, and correctly first: it is the
ceiling on every number the product will ever report. Two cheap halves already shipped — scope
extraction to a declared report region, exclude machinery and known fixtures. The third half needs a
labelled set that does not exist, and **inventing one is the exact failure this product exists to
catch**, so the honest next move is to ship the labelled 40 and ask for more, not to train on our own
labels.

**2 · Make the front door survive a stranger.** §3 above. Smallest change on this list and it gates
every other adoption number, because the wedge is the first command and the first command crashes.

**3 · Per-agent identity.** One token per agent instead of one per fleet. Without it the record
answers "was a claim wrong" but not "which agent is wrong", and the second question is the one that
gets a budget. Larger than the other two and it should not jump them.

## 6 · Real, roadmap, or staged — for the film

Put here rather than at the end, because a submission due **31 August** with a film to shoot is
exactly where this distinction gets quietly lost.

### Real, and I ran it tonight
- `witness` on a done-report — probes git and the filesystem, no database, no credentials.
- `outcome_gate.py` on `fixtures/agent-false-done-PR-BODY.md` — exit 1, BLOCK / PASS / UNVERIFIABLE.
- `pip install -e .` from a clean public clone — exit 0.
- `witness --help` — exit 0.

### Real, on this operator's machine only
- The **41.7% → 8.1%** corpus run. It needs `~/.trace/trace.db`, which exists on one disk on earth.
  A judge cannot reproduce it. **The film may show it; the film must say whose machine it is.**
- The session join, on 427 Claude Code trailers.

### Staged for the demo, and disclosed in the docs already
- **Northwind Parcel** — the test company, its history, its tests and its PRs were written by us.
- The seeded false strings: `docs/auth-migration-2026.md`, `abc1234`, `deadbee`. These are
  deliberately false demo text. They are excluded on the corpus path and still blocking in the
  product's own demo. **A judge who greps the repo will find them** — which is why they are named in
  `docs/ENTERPRISE-CASE-2026-08-27.md` rather than hidden.

### Roadmap, not built
- Per-agent identity · the citation/claim classifier · any harness join beyond Claude Code · any
  install by a person who is not the author.

### The line I would not let the film cross
The four self-catches — wrong repo, wrong denominator, our own fixture counted as a finding, and a
deleted working directory called a liar by a probe that never ran — are the strongest material here
and they are all **true**. The temptation is to present them as designed rigour. They were caught,
late, by other people looking. **Say "caught", not "designed".** A product about false claims that
overstates its own process fails its own gate on camera, and that is the one failure a judge would
remember.
